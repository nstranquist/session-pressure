Find runaway work. Keep the evidence.

Open NDev Pressure → Process Incidents. Select an incident to see the process, its parent, CPU use, memory, evidence times, session when known, and stop history. Alerts open this view.

How detection works

ProcessMinimum ageContinuous CPU evidence
Parent PID 1, or shell parent with PID 110 minutesAt least 60% of one core for 2 minutes
Other work30 minutesAt least 60% of one core for 5 minutes

The resident reuses its existing process inventory. It does not walk the filesystem or read command arguments. Repeated snapshots do not count twice. Missing CPU evidence, changed process identity, or a gap beyond two configured inventory intervals plus one sampling interval resets the evidence (with a minimum tolerance of three minutes). The normal inventory interval is three minutes; low-power profiles can use four minutes or more. Alert timing follows that cadence. Alerts are advisory; detection does not stop work automatically. Long legitimate jobs can also meet these thresholds.

Stop a process

  1. Select the incident. Check the executable, PID, parent, and evidence time.
  2. Select Stop, then confirm. The service verifies the kernel birth identity and user, saves the request, and sends TERM to that one PID.
  3. If the process stays alive, Force Stop becomes available. This is a separate confirmation that sends KILL. It can lose unsaved work.
  4. Read the action history. A sent signal and a confirmed exit are separate results. A failed identity check sends no signal.

A notification link only opens the view. It cannot stop a process. Interactive Stop does not expand to a process tree. The history retains the latest 200 incidents in a private, bounded file. Crash recovery may resend an alert if delivery succeeded before its acknowledgement was saved.

Guard a new scan

Choose a narrow project directory. Add an explicit deadline:

session-pressure processes run --timeout 2m -- rg --files /path/to/project

The runner creates a private process group. At its deadline, or when interrupted, it stops that owned group and saves an incident. Exit status 124 means the deadline or cancellation path ran. The maximum deadline is one hour. This does not impose deadlines on arbitrary scans launched elsewhere.

For expensive scans, use the admission gate too:

ndev session pressure work run --class heavy -- \
  session-pressure processes run --timeout 2m -- rg --files /path/to/project

CLI controls

session-pressure --json processes list
session-pressure --json processes stop --id INCIDENT_ID --confirm
session-pressure --json processes stop --id INCIDENT_ID --force --confirm

processes record --receipt FILE imports an operator-confirmed historical stop. The JSON receipt has pid, ppid, executable (basename), at (RFC3339), and signal (TERM or KILL). These closed records have no kernel identity and cannot authorize a stop.
