Find runaway work. Keep the evidence.

Open NDev Pressure → Process Incidents. Select an incident to see the process, its parent, CPU use, memory, evidence times, session when known, and stop history. Alerts open this view.

How detection works

ProcessMinimum ageContinuous CPU evidence
Known command with parent PID 1, or work below an init-owned shell10 minutesAt least 60% of one core for 2 minutes
Other work30 minutesAt least 60% of one core for 5 minutes

PID 1 is a normal parent for many GUI apps and services. It does not prove that a process is orphaned. The resident reuses its existing process inventory. It does not walk the filesystem or read command arguments. Repeated snapshots do not count twice. Missing CPU evidence, changed process identity, or a gap beyond two configured inventory intervals plus one sampling interval resets the evidence (with a minimum tolerance of three minutes). The normal inventory interval is three minutes; low-power profiles can use four minutes or more. Alert timing follows that cadence. Alerts are advisory; detection does not stop work automatically. Long legitimate jobs can also meet these thresholds.

Stop a process

  1. Select the incident. Check the executable, PID, parent, and evidence time.
  2. Select Stop, then confirm. The service verifies the kernel birth identity and user, saves the request, and sends TERM to that one PID.
  3. If the process stays alive, Force Stop becomes available. This is a separate confirmation that sends KILL. It can lose unsaved work.
  4. Read the action history. A sent signal and a confirmed exit are separate results. A failed identity check sends no signal and records that result. A later inventory can confirm an exit after an earlier Stop request.

A notification link only opens the view. It cannot stop a process. Interactive Stop does not expand to a process tree. The history retains the latest 200 incidents in a private, bounded file. Crash recovery may resend an alert if delivery succeeded before its acknowledgement was saved.

Guard a new scan

Choose a narrow project directory. Add an explicit deadline:

session-pressure processes run --timeout 2m -- rg --files /path/to/project

The runner creates a private process group with a small sleeping supervisor. It removes remaining group members when the command exits, at its deadline, on cancellation, or if the runner itself dies. Deadline and cancellation teardown save an incident. Exit status 124 means the deadline or cancellation path ran. The maximum deadline is one hour. This does not impose deadlines on arbitrary scans launched elsewhere. A descendant that deliberately leaves the private process group is outside this guard. Choose the project scope and deadline before starting work.

For expensive scans, use the admission gate too:

ndev session pressure work run --class heavy -- \
  session-pressure processes run --timeout 2m -- rg --files /path/to/project

CLI controls

session-pressure --json processes list
session-pressure --json processes stop --id INCIDENT_ID --confirm
session-pressure --json processes stop --id INCIDENT_ID --force --confirm

processes record --receipt FILE imports a historical stop or observed exit. The JSON receipt has pid, ppid, executable (basename), at (RFC3339), and signal (TERM, KILL, or NONE). Use NONE when the process had already exited and no signal was sent. An observed exit does not claim that this session stopped the process. These closed records have no kernel identity and cannot authorize a stop.
